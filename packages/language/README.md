# md-publisher-language

The Language bounded context (see `docs/planning/md-publisher/iterations/01/05-architecture-design.md`):
the `.mdpub` grammar and Structure Violation validation.

## What's in the folder?

- `src/md-publisher.langium` — the grammar. A block/inline split (see its own top comment for
  why): Langium only classifies whole lines (heading, thematic break, fenced code block,
  blockquote line, list item line, paragraph text); inline content is parsed separately.
- `src/md-publisher-inline.ts` — the inline-content scanner (emphasis, strong, code spans, links,
  images, cross-references, hard breaks), operating on a block's raw text rather than Langium's
  own CST. A deliberately simplified, non-spec-perfect implementation — see its own top comment.
- `src/md-publisher-util.ts` — parsing helpers for each block type's raw text (`parseHeading`,
  `parseBlockQuoteLine`, `parseListItemLine`, `parseFencedCodeBlock`) and `slugify` (the heading
  anchor algorithm).
- `src/md-publisher-validator.ts` — Structure Violation checks: BR-1/BR-4 (cross-reference
  resolution, Publication-wide, via the inline scanner) and BR-3 (heading-level skips). BR-2
  (front-matter position) is retired — see `docs/planning/md-publisher/iterations/01/08-mvp-plan.md`'s
  Finding 3.
- `src/md-publisher-module.ts` — the DI module wiring the validator into Langium's services.
- `src/generated/` — AST/grammar/module, generated by `langium generate` (gitignored, not
  committed — regenerate with `npm run langium:generate` after editing the grammar).
- `src/index.ts` — the package's public exports.
- `test/` — `block-parsing.test.ts` (grammar-level line classification), `inline-parsing.test.ts`
  (the scanner in isolation), `linking.test.ts` (cross-document anchor resolution), and
  `validating.test.ts` (the Structure Violation checks end to end).

`packages/publishing`'s `compileChapter` is what turns this package's flat, line-at-a-time AST into
actual nested rendering structure (lists, blockquotes) — see its own README.
